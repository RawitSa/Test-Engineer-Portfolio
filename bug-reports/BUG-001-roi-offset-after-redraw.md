# BUG-001 — กรอบ ROI เยื้องจากที่ลาก หลังวาด ROI ใหม่

| หัวข้อ | รายละเอียด |
|--------|-------------|
| Severity | High (กรอบผิดตำแหน่งทำให้ symbol ถูกตัดสินเฟลทั้งที่ผ่าน) |
| Component | วาด / บันทึก ROI ของ symbol (S1) ในแอปตรวจด้วยกล้อง |
| Environment | แอปบนเครื่องทดสอบจริง กล้อง lens ปรับ zoom/focus ด้วยมือ |
| ผู้รายงาน | [Rawit Saowarorangsarit] |

## Steps to reproduce
1. เปิดแอปให้ระบบตามชิ้นงานอยู่ (กรอบ symbol อื่น ๆ ตรงตำแหน่ง)
2. เลือก ROI → วาด ROI ใหม่ของ symbol 1 (ดวงอาทิตย์) โดยลากกรอบครอบ symbol
3. ดูกรอบสีแดงบนหน้าจอแอปหลังบันทึก

## Expected
กรอบที่แสดงตรงกับที่ลาก และครอบ symbol ทั้งดวง

## Actual
กรอบ S1 เยื้องลงล่างประมาณครึ่งกล่อง ยื่นเลยขอบภาพ (ป้าย `out of view`) ส่วน symbol อื่นตำแหน่งถูกต้อง

## Evidence
- ภาพหน้าจอแอป (ก่อน/หลังวาดใหม่) `[แนบ screenshot ใน docs/images/ แล้วลิงก์ที่นี่]`
- รูป template `1Image1.png` ที่บันทึกตรงกับที่ลากพอดี แต่ตำแหน่งที่บันทึกในไฟล์ `1RectangleX/Y/Width/Height.txt` ผิด

## Analysis (แยกข้อเท็จจริงจากข้อสันนิษฐาน)
- ข้อเท็จจริง: รูป template ถูก แต่ตำแหน่งที่บันทึกผิด
- ข้อสันนิษฐานที่ 1: symbol อยู่ชิดขอบล่างของภาพ กรอบที่ลากเลยขอบ รูปถูกตัดแต่กรอบค้นหายังใหญ่เท่าเดิม ตำแหน่งจึงเยื้องไปครึ่งหนึ่งของส่วนที่ถูกตัด
- ข้อสันนิษฐานที่ 2: วาดตอนระบบไม่ได้ตามจออยู่ (สถานะ `searching for the LCD ... 0/21`) ตำแหน่งจึงบันทึกตามที่ลากโดยไม่ชดเชยการขยับ
- วิธีตรวจ: ความสูงรูป + 2 × pad ต้องเท่ากับค่าใน `1RectangleHeight.txt` (pad = 5 px) ถ้าไม่เท่าแปลว่ารูปถูกตัด

## Fix และสถานะ
- ตัดกรอบให้อยู่ในภาพก่อนบันทึก (แสดงข้อความ `box touched the picture edge`)
- ถ้าวาดตอนไม่ได้ตามจอ ให้ขึ้นคำเตือนและถามก่อนบันทึก (ไม่บันทึก → `ROI not saved (LCD not tracked)`)
- เพิ่ม log `ROI compare step N head H: drawn ... -> taught ...`
- ผลทดสอบซ้ำโดยผู้ทดสอบ: **แก้แล้ว** ปัญหาตำแหน่งหายไป
- วิธีแก้ขัดระหว่างรอ: คืนค่า S1 เดิมจากโฟลเดอร์สำรอง
