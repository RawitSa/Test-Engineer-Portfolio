# 01 — ระบบตรวจ LCD symbol ด้วยกล้อง + AI

## บริบท
แอป Windows (C#, WinForms, Emgu CV) ใช้กล้องตรวจว่า symbol บนจอ LCD ของผลิตภัณฑ์แสดงครบ 21 ตัว (S01–S21)
ระบบเดิมใช้ template matching ซึ่งตกง่ายเมื่อภาพเบลอหรือกรอบ ROI คลาดเล็กน้อย
เลนส์ปรับ zoom / focus / exposure ด้วยมือ (ไม่ใช่ auto) และปรับเฉพาะตอนเปลี่ยนเลนส์หรือกล้องมีปัญหา

## โจทย์
1. ลดการตีตกของดีที่เกิดจากภาพเบลอหรือกรอบคลาด
2. **ห้ามให้ของเสียหลุดผ่าน** — ยอมตีตกของดีมากกว่าปล่อยของเสีย
3. ทนต่อการเปลี่ยน zoom และการหมุนชิ้นงาน
4. เช็ค LED หลายดวงพร้อมกัน เลือกได้ว่าดวงไหนต้องติด/ต้องดับ

## สิ่งที่ทำ
- **AI ช่วยตัดสิน symbol**: ชุดภาพเทรน 21,357 ภาพ แบ่งตามคลาส S01–S21 และ NG, โมเดลส่งออกให้ C# ใช้
  ถ้าไม่มีไฟล์โมเดล ระบบกลับไปใช้วิธีเดิมอัตโนมัติ
- **เกณฑ์เข้มงวดเป็นค่าเริ่มต้น**: `ai_min=0.90` (AI ต้องมั่นใจ ≥ 90%), กรณีเลื่อนกรอบต้องได้ ≥ 0.95,
  โหมด `ai=2` ต้องผ่านทั้ง AI และระบบเดิม
- **ชดเชย zoom และวาด ROI ใหม่ทีละ symbol** โดยแปลงตำแหน่งกลับเป็นพิกัดตอนสอน ไม่ต้องสอนใหม่ทั้ง 21 ตัว
- **โหมด multi_led**: ระบุ LED ที่ต้องติดได้ เช่น `1-3,5-7,9-10` หรือ `all` ต้องติดพร้อมกันครบ hold time
  ถ้าเฟลบอกเลขดวงที่ไม่ติด (เช่น `LED not lit: 2,6`) ดวงที่ไม่ได้เลือกไม่ถูกตรวจ

## ผลที่วัดได้ (อ่านพร้อมข้อจำกัด)

| รายการ | ผล | วัดจาก |
|--------|-----|--------|
| ภาพเสียที่หลุดผ่าน (ที่เกณฑ์ 0.90) | ประมาณ 2% | ภาพสังเคราะห์ |
| ภาพดีที่ผ่าน (ที่เกณฑ์ 0.90) | ประมาณ 89% | ภาพสังเคราะห์ |
| ภาพจริงที่เบลอ 21 ภาพ: ระบบเดิม / AI แบบเข้ม | ผ่าน 11 / 14 ภาพ | ภาพจริง แต่กรอบ ROI เป็นค่าประมาณ ไม่ใช่กรอบจริงของแอป |
| ความเร็ว | ประมาณ 5.5 ms ต่อ symbol | วัดบนสภาพแวดล้อมจำลอง ยังไม่ได้วัดบนเครื่องหน้างาน |
| หน้างานจริงหลังแก้ ROI | ผ่าน 20/21 symbol, AI ให้คะแนน 0.98–1.00 | ภาพหน้าจอจากแอปจริง |

**ยังไม่ได้ยืนยัน:** อัตราของเสียหลุดผ่านบนเครื่องจริง ต้องทดสอบกับของเสียจริงหลายแบบ (ปิด segment, บังจอ) ก่อนใช้งานจริง

## ข้อสังเกตจาก code review ที่ยังเปิดอยู่
- ค่า `LastScale` ของระบบตามซูมเป็นตัวแปรร่วมทุกกล้อง ควรแยกต่อ head (ยืนยันในโค้ด: `public static double LastScale` ใน `SymbolAligner.cs`)
- ควรตรวจและกันไม่ให้ AI ตัดสินให้ผ่านใน symbol ที่อยู่นอกภาพ

## ขั้นต่อไปที่วางแผนไว้
- เปิด `ai_collect=1` ประมาณหนึ่งสัปดาห์ เก็บภาพจริงที่ AI ไม่มั่นใจ แยกคลาสแล้วเทรนซ้ำ เพื่อลดช่องว่างระหว่างภาพสังเคราะห์กับหน้างาน
- ทดสอบกับของเสียจริงก่อนเปิดใช้งาน

## บทเรียน
- วัดแยกให้ชัดว่าตัวเลขมาจากภาพสังเคราะห์หรือหน้างานจริง เพราะสองอย่างให้ผลต่างกัน
- เกณฑ์ที่เข้มขึ้นแลกกับการตีตกของดีที่เบลอมาก ซึ่งแก้ได้ด้วยการโฟกัสและวางกล้องให้นิ่ง
- เมื่อเพิ่มความสามารถใหม่ (ตามซูม) ต้อง regression test พฤติกรรมเดิม (การหมุน) เสมอ
