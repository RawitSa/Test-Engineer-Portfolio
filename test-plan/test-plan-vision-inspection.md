# Test Plan — ระบบตรวจ LCD symbol ด้วยกล้อง + AI

เอกสารฉบับย่อ เขียนจากโปรเจกต์ใน [projects/01](../projects/01-vision-inspection.md)

## 1. วัตถุประสงค์
ยืนยันว่าระบบตรวจสอบ symbol ทั้ง 21 ตัวและโหมดเช็ค LED หลายดวงตัดสินถูกต้อง
โดยให้ความสำคัญกับ **ของเสียต้องไม่หลุดผ่าน (false pass)** มากกว่า **ของดีถูกตีตก (false fail)**

## 2. ขอบเขต
**อยู่ในขอบเขต:** การวาดและบันทึก ROI · การตามชิ้นงาน (เลื่อน หมุน ซูม) · การตัดสินด้วย AI และระบบเดิม ·
โหมด multi_led · การทำงานเมื่อไม่มีไฟล์โมเดล
**นอกขอบเขต:** ความถูกต้องของ hardware กล้อง/เลนส์ · การเทรนโมเดลใหม่ (ทดสอบเฉพาะผลลัพธ์)

## 3. ความเสี่ยงและลำดับความสำคัญ
| ความเสี่ยง | ผลกระทบ | การทดสอบ |
|-------------|----------|-----------|
| ของเสียหลุดผ่าน | สูงสุด | TC-AI-03 กับของเสียจริงหลายแบบ |
| ฟีเจอร์ใหม่ทำของเดิมพัง | สูง | TC-ROI-05/06 (regression) |
| กรอบ ROI ผิดตำแหน่ง | สูง | TC-ROI-01..04 |
| ภาพเบลอ / โฟกัสหลุด | กลาง | ทดสอบกับภาพจริงหลายระดับ |
| ภาพสังเคราะห์ไม่เหมือนหน้างาน | กลาง | เปิด `ai_collect=1` เก็บภาพจริงไว้เทรนซ้ำ |
| ความเร็วบนเครื่องหน้างาน | กลาง | วัดเวลาต่อ symbol บนเครื่องจริง (ค่าที่มีเป็นของสภาพแวดล้อมจำลอง) |

## 4. ระดับและวิธีทดสอบ
- **Unit (จำลอง):** parser รายการ LED, logic ตัดสินผ่าน/เฟล (TC-ML)
- **Functional บนเครื่องจริง:** วาด ROI, ตามชิ้นงาน, ผลตัดสินรวม
- **Regression:** รันชุด TC-ROI-05/06 ทุกครั้งที่แก้ระบบตามชิ้นงานหรือซูม
- **Negative / ของเสียจริง:** ตัวอย่างของเสียหลายแบบ (ปิด segment, บังจอ)
- **Exploratory:** เปลี่ยนเลนส์ ปรับโฟกัส/exposure ด้วยมือ

## 5. สภาพแวดล้อม
เครื่องทดสอบ Windows ที่ใช้หน้างาน · กล้อง/เลนส์ชุดจริง ปรับ zoom/focus/exposure ด้วยมือ · ชิ้นงานดีและของเสียที่รู้ผลแน่นอน

## 6. เกณฑ์เริ่มและจบ
- **เริ่ม:** build ผ่าน, มีไฟล์โมเดลและ config ครบ, มีชิ้นงานดี/เสียตัวอย่าง
- **จบ:** ไม่มี Critical/High ค้าง · TC-AI-03 ไม่มีของเสียหลุดผ่านในตัวอย่างที่ตกลงกัน · regression ผ่าน
